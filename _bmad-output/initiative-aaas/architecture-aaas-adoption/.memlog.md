- (constraint) Hérité de la spec : backend C# .NET + Entity Framework, frontend Angular, auth JWT, CQRS [ADOPTED]
- (constraint) Hérité de la spec : expiration réservation 15 min, max 2 réservations actives par membre, 1 réservation active par animal, email admin à chaque réservation et formulaire contact
- (constraint) Hérité UX : mode clair uniquement, mobile-first, admin téléphone + ordinateur
- (event) Contexte existant : FitClub (server/) en .NET 10 (net10.0), EF Core 10.0.12 SqlServer, JwtBearer 10.0.12, dossiers par feature (Auth, Sessions, Data, Common) ; gym-app/ en JS vanilla
- (direction) Mode accompagné (coaching path) choisi
- (assumption) Livrable = spine seule (guide de build) ; pas de rendu additionnel demandé, à reproposer au Finalize
- (decision) Cible actuelle : exécution en local sur le PC du développeur ; mise en ligne différée (Deferred)
- (decision) Base de données : SQL Server (LocalDB en local, comme FitClub) via EF Core ; binds tout le stockage relationnel, prevents divergence de provider entre slices
- (decision) Photos : fichiers sur disque local servis par l'API, derrière une abstraction de stockage unique (seul point d'accès aux fichiers) pour migrer vers un stockage cloud plus tard
- (decision) Emails : envoi SMTP réel via un compte Google (Gmail) ; identifiants hors du code (user-secrets / variables d'environnement)
- (version) .NET 10 / EF Core 10.0.x / JwtBearer 10.0.x : alignés sur FitClub (vérifié dans server/FitClub.Api.csproj, 10.0.12)
- (version) Angular 22 (sortie 2026-06-03, active jusqu'en 06-2027) : version à utiliser (web, 2026-10)
- (version) Gmail SMTP : smtp.gmail.com 587 STARTTLS, mot de passe d'application + validation en 2 étapes requise ; Less Secure Apps fermé depuis 2025-05 (web, 2026-10)
- (version) MediatR passé sous licence commerciale (Lucky Penny, 2025) ; gratuit en Community sous 5 M$ de CA ; 12.x reste Apache sans mises à jour (web, 2026-10)
- (decision) CQRS : interfaces maison ICommandHandler<TCommand,TResult> / IQueryHandler<TQuery,TResult> enregistrées en DI, appelées par les endpoints ; pas de MediatR ni de librairie de médiation ; prevents deux mécanismes de dispatch
- (decision) CQRS : une seule base ; requêtes en lecture seule (AsNoTracking) projetées directement en DTO, jamais d'entité exposée ; seules les commandes modifient l'état
- (decision) Organisation : un dossier par fonctionnalité (Animaux, Reservations, Actualites, Favoris, Contact, Auth) contenant commandes, requêtes, endpoints
- (decision) Expiration 15 min : option C ; chaque réservation stocke ExpiresAt ; toute commande/requête traite EnAttente avec ExpiresAt <= maintenant comme Expirée (exactitude) ; un BackgroundService périodique (~30 s) persiste Expirée et remet l'animal Disponible (ménage)
- (decision) Course à la réservation : l'unicité d'une réservation active par animal est garantie par la base (contrainte/verrou), pas seulement par le code
- (decision) Paradigme : vertical slices dans un seul projet API (+ projet de tests) ; chaque fonctionnalité est propriétaire de ses entités et seule à les modifier ; pas de Clean Architecture multi-projets
- (decision) Auth : reprise du modèle FitClub — PasswordHasher<User> d'ASP.NET Core Identity (sans Identity complet), JWT Bearer HS256, rôles Membre/Admin en claim, policy Admin sur chaque endpoint admin
- (decision) Compte admin créé au démarrage depuis la configuration (seed) ; aucune inscription admin via le site
- (decision) Jeton JWT stocké côté client dans localStorage, envoyé par un intercepteur HTTP Angular
- (question) Revoir le stockage du jeton (cookie httpOnly + CSRF) avant toute mise en ligne publique
- (decision) Front : Angular 22, composants standalone + signals, un dossier par fonctionnalité, état via services à signals, pas de NgRx
- (decision) UI : CSS maison à partir des jetons de DESIGN.md exposés en variables CSS ; pas d'Angular Material ni de librairie de composants
- (decision) Dev local : API .NET et ng serve séparés, proxy Angular vers l'API ; code dans aaas/api (solution .NET + tests) et aaas/web (Angular) à la racine du projet
- (event) Reviewer Gate : rubric (0 crit, 4 high), versions (0 crit, 2 high), adversarial (3 crit, 12 high) ; revues dans reviews/
- (decision) Forcer le statut d'un animal ayant une réservation active : refusé, 409 reservation-active
- (decision) Supprimer un animal ayant des réservations (actives ou passées) : refusé, 409 animal-a-des-reservations ; photos et favoris supprimés en cascade sinon
- (decision) Échec d'envoi de l'email après commit : la réservation reste valide, erreur journalisée, pas de file de réessai
- (decision) Photos : JPEG, PNG ou WebP ; 5 Mo max par photo ; 10 photos max par animal
- (decision) Tests backend : xUnit v3 (xunit.v3) plutôt que v2
- (decision) Email : MailKit (>= 4.16, actuel 4.18.1), StartTls port 587 ; SmtpClient déconseillé par Microsoft
- (version) .NET 10.0.13 (sécurité, 2026-10-13) pour EF Core, JwtBearer, Mvc.Testing ; SDK 10.0.402 ; Angular 22.2.x / TypeScript 6.0.x / Node ^22.22.3||^24.15.0 (poste : 24.15.0) ; ng new 22 : standalone, zoneless, OnPush, Vitest ; LocalDB SQL Server 2025 (17.0)
